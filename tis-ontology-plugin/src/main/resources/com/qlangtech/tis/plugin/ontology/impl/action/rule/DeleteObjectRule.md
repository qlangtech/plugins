## cascadeDelete

**级联删除模式**

控制删除对象时如何处理与该对象相关的链接关系：

- **false（默认）**: 仅删除对象本身
  - 如果对象存在关联的链接，删除操作可能失败
  - 适用于需要保留数据完整性的场景
  
- **true**: 级联删除
  - 删除对象的同时，自动删除所有指向该对象的链接
  - 删除所有从该对象指向其他对象的链接
  - 适用于彻底清理数据的场景

**示例**：

假设有对象 A，存在以下链接：
```
B → A (其他对象指向 A)
A → C (A 指向其他对象)
```

- `cascadeDelete=false`: 仅删除 A，链接 B→A 和 A→C 仍然存在（可能导致数据不一致）
- `cascadeDelete=true`: 删除 A 以及链接 B→A 和 A→C

**注意事项**：
- 级联删除操作不可逆，请谨慎使用
- 建议在测试环境验证后再在生产环境使用
- 大量级联删除可能影响性能

## confirmationRequired

**二次确认机制**

控制删除操作是否需要用户明确确认：

- **true（默认）**: 需要确认
  - 执行删除前，必须在参数中传入 `deleteConfirmed=true`
  - 防止误操作导致的数据丢失
  - 推荐在生产环境使用
  
- **false**: 不需要确认
  - 直接执行删除操作
  - 适用于自动化流程或批量删除场景

**实现方式**：

在调用 Action 时，传递确认参数：
```json
{
  "rid": "object_rid_to_delete",
  "deleteConfirmed": true
}
```
