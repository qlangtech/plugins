# EnableChatBI 插件简介

## 插件概述

EnableChatBI 是 TIS 数据集成平台中的智能问数插件，它让用户能够用自然语言提问，系统自动生成 SQL 并执行查询，无需编写复杂的 SQL 语句。这个插件通过大语言模型（LLM）的推理能力，将业务人员的日常问题转化为精准的数据查询，大幅降低数据分析的技术门槛。

## 核心作用

- **自然语言到SQL的智能转换**：接收用户的中文问题（如"上个月销售额是多少？"），自动生成对应的 SQL 查询语句，并执行返回结果
- **GraphRAG知识检索**：基于 Neo4j 图数据库存储的本体知识（表结构、字段语义、业务术语等），智能检索相关的数据模型信息，为 SQL 生成提供精准上下文
- **多层SQL安全校验**：内置关键字白名单检查、AST 语法树分析、EXPLAIN 执行计划验证三重防护机制，确保生成的 SQL 安全可靠，防止误操作和恶意查询
- **智能重试与追踪**：当 SQL 生成失败或执行出错时，自动分析原因并重试；完整记录每次问答的 Trace 日志，便于问题排查和效果优化

## 适用场景

- **业务人员自助查询**：销售、运营等非技术人员需要快速获取数据报表，但不熟悉 SQL 语法
- **临时数据探索**：数据分析师在探索性分析阶段，需要频繁试探不同维度的数据，用自然语言比手写 SQL 更高效
- **数据看板问答**：在 BI 看板或数据大屏中集成问答能力，让管理层随时提问获取关键指标
- **API化数据服务**：将智能问答能力封装为 API，供其他系统调用，实现数据查询能力的对外开放

## 工作机制

1. **启用时触发同步**：配置并保存该插件后，系统会自动将本体定义（表、字段、关系、业务术语等）全量同步到嵌入式 Neo4j 图数据库，建立知识图谱
2. **用户提问流程**：用户输入自然语言问题 → GraphRAG 检索相关本体知识 → LLM 根据知识生成 SQL → 三层校验（关键字检查、AST 分析、EXPLAIN 验证）→ 执行查询 → 返回结果
3. **智能重试机制**：若 SQL 校验失败或执行报错，系统会分析错误原因，自动调整 Prompt 并重新生成 SQL，最多重试 2 次
4. **Trace 日志管理**：每次问答的完整过程（问题、检索结果、生成的 SQL、校验步骤、执行结果）都会记录到 Trace 日志中，支持按域自动清理（默认保留 7 天，最多 1000 条）

## 使用建议

- **首次配置**：务必先完成本体定义（表、字段语义、业务术语、同义词等），本体信息越完整，SQL 生成的准确率越高
- **选择合适的LLM**：建议使用支持长上下文（8K+）的大模型，如通义千问等，以便容纳更多的本体知识和历史对话
- **校验策略调优**：生产环境建议开启全部三层校验（关键字白名单、AST、EXPLAIN），测试环境可适当关闭 EXPLAIN 以提升速度
- **定期查看Trace**：通过 Trace 日志分析用户的提问模式和 SQL 生成质量，持续优化本体定义和业务术语词典
- **结果集限制**：默认最多返回 200 行结果，避免大查询影响数据库性能；查询超时设为 30 秒，防止慢查询阻塞
